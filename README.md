# tandem-java

Pure Java implementation of [Tandem8x32](https://github.com/tandem-rng/spec), a noncryptographic
pseudorandom number generator. It produces the specified stream bit for bit.
It is fast on CPUs, and the optional `tandem-rng-cuda` module fills on NVIDIA GPUs.

## Install

The artifact is `tandem-rng`. Java 25 or later, no native code, no runtime dependencies.

```sh
pixi run test        # mvn -B verify
```

## Use

```java
import io.github.tandemrng.Tandem;

Tandem rng = Tandem.seed(42);                  // 128-bit seed with whitening, default K
double x = rng.nextDouble();
int[] words = new int[1 << 20];
rng.fill(words);                               // the values of repeated nextInt()
int i = rng.nextInt(10);                       // uniform in [0, 10), Lemire
double g = rng.nextGaussian();                 // Box-Muller from two double draws
double e = rng.nextExponential();              // -ln(1 - u) from one double draw
Tandem worker = rng.split(7);                  // by index, from the key alone
Tandem[] kids = rng.fork(4);                   // from the current block, parent moves on
double y = rng.atDouble(1000);                 // element 1000 of the fill from here, no move
```

GPU fill, in the `cuda/` module:

```java
try (TandemCuda gpu = TandemCuda.open(); Arena arena = Arena.ofConfined()) {   // device 0
    double[] a = new double[1 << 24];
    gpu.fill(a, rng);                                           // the values of rng.fill(a)
    MemorySegment d = gpu.fillDoubles(arena, 1L << 28, rng);    // device memory
}
```

## What it provides

- `Tandem`: key, position and chunk length `K`, with `Tandem(int[] key, long position, int k)`
  and `Tandem.seed(lo, hi, k)`. It is `Serializable` and not thread-safe.
- Every specification type: `boolean`, `byte`, `short`, `int`, `long`, 128-bit `{lo, hi}`,
  `float`, `double`, binary16 bits, `char`, complex `{re, im}`. Fills for the array types.
- `atDouble` and the other `at` methods read at a position without advancing.
- `split(i)`, `fork(n)`, `sub(purpose)`, `setPosition`, `key()`, `position()`, `chunkLength()`.
- Bounded integers: `nextInt(bound)`, `nextLong(bound)`, `nextInts`, `nextLongs`,
  `belowU32`, `belowU64`, `fillBelowU32`, `fillBelowU64`. They use Lemire's method.
- Normals: `nextGaussian`, `nextGaussianFloat`, `nextGaussian2`, `nextGaussianFloat2`,
  `fillGaussian(double[] | float[])`. Double normals agree with other ports to 1e-12 relative.
- Exponentials: `nextExponential`, `nextExponentialFloat`, `fillExponential`.
  They are bit identical to `tandem-c` and `tandem-cuda`.
- `java.util.random.RandomGenerator.SplittableGenerator`, so it drives `ints()`, `doubles()`,
  `splits()` and `Collections.shuffle`.
- `TandemProvider` for Apache Commons RNG. Add `commons-rng-client-api` to use it.
- Parallel use: element `i` of a fill is draw `i`, so any decomposition reproduces a serial run
  ([Appendix B](https://github.com/tandem-rng/spec/blob/main/SPEC.md#appendix-b-parallel-decomposition-non-normative)).
- GPU, `TandemCuda` in `cuda/`: `open()`, `fill`, `fillBelowU32`, `fillBelowU64`, `fillGaussian`
  on arrays, and `fillInts`, `fillLongs`, `fillFloats`, `fillDoubles`, `fillGaussianFloats`,
  `fillGaussianDoubles` into device memory. It needs compute capability 8.0 and driver 570.
  Run the JVM with `--enable-native-access=ALL-UNNAMED`.

Normal pairs, bounded fill contracts, draw widths and the GPU kernels are in
[docs/notes.md](docs/notes.md).

## Tests

```sh
pixi run test        # mvn -B verify, JDK 25
cd cuda && pixi run test && pixi run gpu-test    # gpu-test needs a GPU host
```

- `VectorsTest` checks every vector of the spec, from `vectors.json` through `tools/gen_vectors.py`.
- `StreamsTest` checks stream dumps in `src/test/resources/data`, copied from `tandem-c`.
- `DerivedTest` and `ExponentialTest` check bounded, normal and exponential values against
  `tandem-cuda` fixtures, generated by `tools/gen_derived.cpp`.
- `FillsTest` checks fills against scalar draws at cut offsets. `TandemCudaTest` checks GPU fills.
- CI runs JDK 25 and 27 on Linux and macOS.

## Speed

One thread, `pixi run bench`, Apple M4 Pro, JDK 25.0.2 (Azul Zulu). Minimum of seven runs after
three warm-up runs. Nanoseconds per scalar draw, GiB/s for arrays of 2^24 elements.

| generator | nextInt ns | nextLong ns | nextDouble ns | nextGaussian ns | int[] loop GiB/s | double[] loop GiB/s | int[] fill GiB/s | double[] fill GiB/s |
|---|---|---|---|---|---|---|---|---|
| Tandem | 1.22 | 1.72 | 1.95 | 4.41 | 2.98 | 3.86 | 5.64 | 6.33 |
| L64X128MixRandom | 1.13 | 1.10 | 1.12 | 3.35 | 3.32 | 6.60 | - | - |
| SplittableRandom | 0.43 | 0.48 | 0.61 | 2.23 | 9.38 | 14.74 | - | - |
| Random | 3.98 | 7.97 | 7.96 | 13.76 | 0.07 | 0.13 | - | - |

Exponentials, same machine and method:

| generator | nextExponential ns | `fillExponential(double[])` GiB/s | `fillExponential(float[])` GiB/s |
|---|---|---|---|
| Tandem | 3.00 | 2.89 | 2.02 |
| L64X128MixRandom | 3.55 | - | - |

`fillGaussian` runs at about 2.3 GiB/s for `double[]` and 1.4 GiB/s for `float[]`.

GPU: NVIDIA A100 40 GB (PCIe), driver 570.124, JDK 25, `pixi run bench` in `cuda/`. GiB/s written
by each device fill. Minimum of 21 samples of ten launches. The last column is the `tandem-cuda`
README figure for the same kernel.

| fill | 2^26 GiB/s | 2^28 GiB/s | tandem-cuda 2^28 GiB/s |
|---|---|---|---|
| `fillInts` | 1333 | 1385 | 1383 |
| `fillLongs` | 1367 | 1390 | 1395 |
| `fillFloats` | 1328 | 1381 | 1383 |
| `fillDoubles` | 1365 | 1392 | 1394 |
| `fillBelowU32`, range 1000 | 1288 | 1340 | 1336 |
| `fillBelowU64`, range 1000 | 1326 | 1356 | 1348 |
| `fillGaussianFloats` | 1140 | 1200 | 1290 |
| `fillGaussianDoubles` | 712 | 720 | 765 |

Array fills copy over PCIe: `fill(double[])` of 2^26 elements runs at 9.3 GiB/s. Keep data on the
device when a GPU consumes it.

## AI assistance

This port was written with the help of large language models under human
direction. The design and the specification are human work, as is much of the
Julia implementation. The code is tested bit for bit against every vector of
the specification and against long stream dumps from the Julia implementation,
and every value must match. The output does not depend on who or what wrote the
code.
